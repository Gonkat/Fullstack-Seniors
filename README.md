# Модус Сигнал

MVP системы обратной связи и предложений сотрудников ГК «Модус Трейд» — работающий продукт для хакатона.

Единый канал, в котором сотрудник описывает проблему или предлагает улучшение, система регистрирует обращение и направляет его ответственному по категории, а автор видит статус, уточнения и итоговое решение. Руководитель получает входящие, сроки по SLA и аналитику повторяющихся проблем.

**Текущий backend — Mokky.dev** (бесплатный временный API и хранилище). Клиент работает с ним напрямую, поэтому для демонстрации не нужен собственный сервер. Фронтенд собран на **Astro 5 + Preact**: Astro отвечает за страницу и сборку, Preact-остров — за интерактивные экраны. Архитектура позволяет переключиться на собственный API с SQL одной настройкой в `src/lib/config.js` — без переписывания экранов и бизнес-логики.

- Продуктовая и техническая концепция: [`docs/КОНЦЕПЦИЯ.md`](docs/КОНЦЕПЦИЯ.md)
- UML-модель: [`docs/UML.md`](docs/UML.md)
- План защиты и демонстрации: [`docs/ЗАЩИТА.md`](docs/ЗАЩИТА.md)
- Демо-данные: 22 обращения (20 из датасета + 2 связанных), 20 пользователей, 18 категорий
- Сквозной тест собственного API: `npm test` (36 проверок)
- Проверено в браузере: вход, создание, комментарии, статусы, решение, подтверждение автора, аналитика, админка, сохранение после перезагрузки

## Быстрый запуск

Нужен Node.js **20.3+** (Astro 5). База данных и платный хостинг не требуются.

```bash
npm install
npm run dev
```

Откройте <http://localhost:4321>. Astro-клиент загрузит данные из Mokky.dev; API не нужен.

Сборка и запуск как на стенде:

```bash
npm run build
npm start
```

`npm start` собирает Astro и поднимает Express на <http://localhost:3000> — он отдаёт `dist/` и API. Для проверки только API: `npm run server`; предпросмотр сборки Astro: `npm run preview`.

- Демо-данные уже загружены в ресурс `/test` проекта Mokky. Повторное наполнение: `npm run seed:mokky` (очищает ресурс и записывает 22 обращения).
- Сброс из интерфейса: «Администрирование» → «Сбросить демо-данные» (занимает около 15–25 секунд: 151 запись создаётся реальными POST-запросами).
- Собственный API вместо Mokky: `apiMode: 'server'` в `src/lib/config.js`, затем `npm run build && npm start` (Express отдаёт и статику, и API). В режиме разработки Astro проксирует `/api` на `localhost:3000`, поэтому можно запустить `npm run server` отдельно.
- Тест API: `npm test` (порт 3411, временный `DATA_DIR`, рабочие данные не затрагивает).

Публикация: каталог `dist/` после `npm run build` — обычный статический сайт. `seed.json` копируется в `dist/` из `public/`; для сброса он должен быть доступен рядом с `index.html`. Старый vanilla-фронтенд сохранён в `legacy/` как страховка и не участвует в сборке.

## Настройка Mokky.dev

1. Проект: `https://152474a5c2924bce.mokky.dev`, ресурс `/test` (уже создан и наполнен).
2. Базовый адрес и имя ресурса заданы в `src/lib/config.js` → `mokky.baseUrl`, `mokky.collection`.
3. **Загрузка файлов.** Чтобы вложения любого размера хранились как файлы, включите в настройках проекта Mokky.dev «Загрузка файлов» — появится ресурс `/uploads`. Без него клиент сохраняет файл до 0,7 МБ прямо в записи обращения (data-URL), а больший файл вернёт понятную ошибку с просьбой включить загрузку.
4. **Ограничения Mokky.dev:** ресурсы создаются только через панель, `id` генерируется сервером (приложение хранит стабильный ключ в поле `uid`), лимит тела запроса около 1–2 МБ, 800 запросов в минуту. Для MVP этого достаточно; при росте нагрузки — собственный backend.
5. **Безопасность:** ресурс Mokky публичный, поэтому в этом режиме роли проверяются в браузере. Это временная схема для синтетических демо-данных. Собственный API (`apiMode: 'server'`) проверяет права на сервере; целевая версия — SSO + PostgreSQL.

Если нужно разделить сущности по ресурсам, создайте в Mokky коллекции и измените адаптер `src/lib/backend.js`; текущая схема хранит все сущности в одном ресурсе с полем `entity`, что упрощает бесплатный демо-стенд.

## Демо-сценарий (7–10 минут)

1. **Вход сотрудником** (Анна Соколова). Показать «Мои обращения», статусы, сроки, просрочки и уведомления.
2. **Создать обращение**: тип «Проблема», категория «Планирование ресурсов», высокий приоритет. Справа видно ответственного по правилу категории (Андрей Титов), срок первого ответа и рассмотрения. Приложить файл-заглушку, отправить — обращение получает номер `A-023` и сохраняется в Mokky.
3. **Войти руководителем** (Андрей Титов). В «Входящих» открыть обращение: добавить комментарий, запросить уточнение, назначить другого ответственного, изменить приоритет или срок.
4. **Вернуться автором** и ответить на уточнение — обращение автоматически вернётся «На рассмотрении» с записью в истории.
5. **Руководителем зафиксировать решение**: «Реализовано» с текстом решения и действиями. Автор получит уведомление и увидит решение.
6. **Автором подтвердить закрытие** — статус «Закрыто».
7. **Показать аналитику**: KPI, типы, статусы, средний первый ответ, просрочки, повторяющиеся проблемы («Каталог и данные», «Документооборот»).
8. **Администратором** показать категории и правила маршрутизации, роли, сброс демо-данных.

Готовый мотивированный отказ: **A-017** — «Отклонено» с обоснованием (нет помещения), автору доступна причина.

## Архитектура

```
src/ (Astro 5 + Preact)
  pages/index.astro    страница и точка входа Astro
  layouts/Layout.astro общий HTML-каркас и глобальные стили
  components/App.jsx   состояние, роутинг, сессия
  components/*View.jsx вход, список, карточка, форма, аналитика, админка
  lib/config.js        централизованная конфигурация: режим, адрес API, лимиты
  lib/domain.js        статусы, переходы, SLA, права, маршрутизация
  lib/views.js         карточки, списки, аналитика, админка
  lib/mutations.js     создание, комментарии, решения, категории
  lib/backend.js       адаптер: Mokky.dev (по умолчанию) или собственный /api
  styles/global.css    стили интерфейса

public/
  seed.json            демо-набор для наполнения и сброса
  shared/              исходные CommonJS-модули для server/ и тестов

legacy/                старый vanilla-фронтенд, не участвует в сборке

server/                опциональный собственный backend
  index.js             HTTP-транспорт, файлы, статика dist/
  store.js             JSON-хранилище для локального режима
  seed.js              генерация демо-данных
```

В режиме Mokky `src/lib/backend.js` загружает записи, применяет общие правила из `src/lib/*` и сохраняет изменения точечными запросами. В серверном режиме те же правила выполняет Node API, а клиент только отправляет запросы. Поэтому переход на SQL не требует изменений экранов.

```
Браузер ──► Astro/Preact ──► src/lib/backend.js ──► Mokky.dev /test
                                             └──► собственный /api ──► PostgreSQL
```

## API (контракт)

Все запросы, кроме `GET /api/users` и `GET /api/health`, требуют пользователя. В серверном режиме — заголовок `x-user-id`; в режиме Mokky пользователь передаётся адаптером.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/bootstrap` | пользователь, справочники, счётчики |
| GET | `/api/appeals` | список с фильтрами (`scope`, `q`, `type`, `status`, `priority`, `categoryId`, `department`, `overdue`, `sort`) |
| POST | `/api/appeals` | создание и маршрутизация |
| GET | `/api/appeals/:id` | карточка, история, права |
| PATCH | `/api/appeals/:id` | статус, ответственный, приоритет, срок |
| POST | `/api/appeals/:id/comments` | комментарий или внутренняя заметка |
| POST | `/api/appeals/:id/decision` | решение «Реализовано / Отклонено» |
| GET | `/api/analytics` | KPI и разрезы в зоне видимости |
| GET/POST | `/api/notifications`, `/api/notifications/read` | уведомления |
| GET | `/api/admin/overview` | администрирование |
| PATCH/POST | `/api/categories/:id`, `/api/categories` | категории и правила |
| POST | `/api/admin/reset` | восстановление демо-набора |
| GET | `/api/attachments/:id` | файл (серверный режим) |

## Известные ограничения

- **Mokky.dev — временная инфраструктура.** Публичный ресурс без серверной авторизации; роли в этом режиме проверяются в браузере. Не подходит для реальных персональных данных.
- **Нет транзакций между записями.** Обращение, событие и уведомление сохраняются несколькими запросами; при обрыве связи возможна частичная запись. В собственном API это одна транзакция.
- **Сброс демо-данных занимает 15–25 секунд** (151 POST-запрос).
- **Вложения:** полный размер требует включённого ресурса `/uploads` в Mokky; иначе встроенный файл до 0,7 МБ.
- **Один ресурс Mokky** с полем `entity`; при необходимости нормализации — отдельные коллекции и правка адаптера.
- **Серверный режим** использует JSON-файл для локального запуска; целевая СУБД — PostgreSQL (описано в концепции).
- **Нет фоновых задач**: SLA рассчитывается при чтении, автоматических эскалаций и e-mail нет.
- **Анонимная подача** не включена: для рассмотрения нужны уточнения и обратная связь автору.

Данные синтетические: реальные клиенты, сделки, контрагенты и сотрудники не используются. Предзаполненных вложений в демо-наборе нет — загрузка файлов проверяется при создании обращения.
